Field Notes

What we heard from the dark

Six symptoms kept echoing through the loop map — each one a reinforcing circuit where failure produced no message, and no message produced retry. They are recorded here exactly as they surfaced.

Loop 1 · The Silent Reset

Whisper's 5-second READY_TIMEOUT vs a cold model load creates a reinforcing loop: it fails with no message, the user retries the same way, it fails again.

cold load → 5s timeout → no message → retry → fail

Loop 2 · Resample-or-Reject

A forced 16kHz mono int16 InputStream vs BlackHole's native 48k stereo creates the second loop: PortAudio rejects, open-failed fires, the UI resets to Idle.

16k demand → PortAudio rejects → open-failed → Idle

Loop 3 · The Name Doubles

A device-name string passed to sd.InputStream may resolve to the output instance when duplicate names exist — a deterministic, invisible open failure.

duplicate name → wrong instance → deterministic fail

Loop 4 · Hog-Mode Hold

The call app's hog-mode mic lock (Zoom/Teams at the HAL layer) blocks a second InputStream open; stream.read dies instantly and _on_live_ended_naturally resets in silence.

HAL hog → 2nd open blocked → read dies → silent reset

Loop 5 · Too Hot for Silence

VAD SILENCE_RMS = 350 is too hot for an attenuated loopback: the low-volume far-end never crosses threshold, the session stays Live but deaf — reported as "didn't work".

attenuated loopback → RMS never > 350 → Live-but-silent

Loop 6 · The No-Routing Trap

BlackHole selected while call output still goes to the speakers means capturing digital silence — and silence is not an auto-stop. Two failure modes, conflated.

output → speakers → capture → silence → no auto-stop → confusion

Technique II · Fishbone Diagram

Dissecting the dead fish

If the loops tell us how failure reproduces, the spine tells us where it hides. Four ribs of cause, head pointed straight at the effect: "capture fails in-call".

Fishbone · four ribs, one effect: capture fails in-call

Tools

  • No input-level meter — the one gauge that would expose silence instantly.
  • No audible monitor of what the app actually hears.
  • No preflight open test before commit.
  • No log of the open-failed exception text — the truth is thrown away.

Environment

  • macOS demands an aggregate / multi-output device to hear and capture at once.
  • Unplugging or display sleep re-clocks the device mid-session to 48k.

Process

  • TEST-PLAN F7 says "play a German video"; the user tested a live call.
  • Echo-cancellation and duplex load are simply not covered by the checklist.

People

  • Default device is the mic, so the call far-end is never heard at all.
  • The user must discover Core Audio routing themselves — the app never guides.
Technique III · The Disney Method

Three rooms, one idea at a time

Dream in the sky, plan at the workbench, storm in the dark. Nobody was allowed to be in two rooms at once.

The Dreamer
room 1 · no limits
  • A live level meter on the capture page, plus a "Test Device" 2-second button that proves the pipeline before you ever join a call.
  • Auto native-rate capture with an internal resample down to 16k — the app adapts to BlackHole, never the reverse.
  • Dual-capture: microphone and loopback mixed into one stream, so you hear both sides of the call.
  • A guided BlackHole routing wizard that walks the user through aggregate-device setup step by step.
The Realist
room 2 · how it actually ships
  • Query the device's native rate via sd.query_devices(), open the stream at that rate, resample in Python.
  • Pass the device index, never the name — indices can't resolve to the wrong instance.
  • Surface ensure_running failed with the reason — make the invisible visible.
  • Extend the Whisper READY window to 30s for cold starts.
The Critic
room 3 · what bites back
  • Resampling adds CPU on a machine already running a local LLM.
  • Dual-capture doubles the Whisper load — twice the audio, twice the transcribe.
  • A longer timeout slows Start feedback; dead air feels like a hang.
  • Index persistence breaks across reboots — CoreAudio renumbers devices freely.
⚡ The Leverage Point
"Break the silence with diagnostics — show the exact open exception, the Whisper state, the live RMS. The silent reset is the root amplifier."
Every other fix is downstream of the ability to see what failed.
◈ Synthesis · The Climax

The session collapsed six causes into two failure modes that were being conflated. What looked like one bug is actually two diseases wearing one symptom:

Mode A · auto-stop

= open-failed (rate / index / hog) or Whisper 5s timeout — both ending in a silent reset.

Mode B · silent-live

= VAD threshold too hot plus the no-routing trap. It "runs" forever, hearing nothing.

Ranked Root Causes

Six suspects, arraigned in order

1prime

Whisper 5s timeout → silent reset

The cold model never finishes loading before READY_TIMEOUT expires, and the failure surfaces as nothing at all. It is the root amplifier: it converts every other fault into an unexplanable auto-stop and sends the user into retry-loop R1.

blast radius
2prime

Forced 16kHz vs BlackHole's native rate

Asking PortAudio for 16k mono int16 on a 48k stereo loopback is a resample-or-reject wager the app always loses. Open-failed fires, the UI snaps to Idle, and the exception text vanishes unlogged.

blast radius
3latent

Device-name vs device-index

Names collide — BlackHole 2 ch exists as both input and output. A name lookup can deterministically bind the input stream to the output instance and fail every time, invisibly.

blast radius
4latent

Call-app hog-mode

Zoom/Teams lock the mic at the HAL layer. The second InputStream open is blocked, stream.read dies instantly, and _on_live_ended_naturally resets the UI as if the user had stopped it.

blast radius
5insidious

VAD SILENCE_RMS = 350 threshold

Too hot for an attenuated loopback signal. The far-end voice never crosses threshold, the session sits Live and mute, and the honest user report is simply: "didn't work".

blast radius
6insidious

The no-routing trap

Select BlackHole in the app, leave call output on the speakers, and you are recording perfect digital silence — which is not an auto-stop, which is why it masquerades as every other failure. The conflation itself is the disease.

Direction of Travel

The fix map — in the order it must happen

Diagnostics before optimization: you cannot fix what you cannot see. Everything below traces back to a ranked cause above.

01

Diagnostics first

Surface the exact open exception, Whisper state, and live RMS. No more silent resets — the root amplifier dies here.

kills amplification of #1–#4
02

Native rate + resample

Query the device's native rate with sd.query_devices, open at that rate, resample to 16k in Python. Accept the CPU cost — it buys reliability.

fixes #2 · counters #4's re-clock trap
03

Device index, not name

Bind streams by integer index resolved from the input-bearing device list; re-resolve at start so reboots and renumbering can't strand the pick.

fixes #3
04

Longer ready timeout

Extend Whisper READY_TIMEOUT from 5s to 30s for cold starts — and show a countdown so waiting never feels like hanging.

fixes #1
05

Level meter + Test button

A live input meter plus a 2-second Test Device preflight. Silent capture becomes visible in one glance; VAD tuning gets a ground truth.

fixes #5 · exposes #6
06

Routing wizard

A guided BlackHole setup: build or verify the aggregate / multi-output device so the user can hear the call and capture it. No more discovery-by-despair.
